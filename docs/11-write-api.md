# 11. Создание и изменение документов в HCM

AI Assistant умеет не только читать, но и создавать и изменять объекты HCM:
агенты сервера, удалённые действия, курсы, мероприятия и другие. То есть делает за пользователя
всю ручную работу. Пользователь пишет в LLM-клиенте «Создай шаблон увольнения по причине
замены сотрудника нейросетью, который создает заявку с новым типом ДО, уведомлениями и т.п.» или 
«Назнать курс "Курс для кадровиков" всем сотрудникам подразделения отдела кадров». Модель находит объекты, 
генерирует поля и значения, ассистент проверяет поля, связи, типы и создаёт нужные 
документы с переменными, кодом и полями. Пользователю она отвечает названием и id созданных документов.
А пользователь может в админке по id проверить и закрыть заадчу))

По умолчанию запись **выключена**: ассистент только читает базу. Чтобы
включить запись, администратор HCM один раз выполняет шаги ниже.

## Как это устроено

- Ассистент пишет через **коробочный Open API**, встроенный в HCM (`/oapi/…`).
  Документ сохраняется так же, как из админки: платформа выдаёт id, заполняет
  даты и автора, вызывает обработчики сохранения. В базу напрямую ассистент
  не пишет, его пользователь базы остаётся только на чтение.
- Перед записью ассистент проверяет и валидирует данные по схеме объекта: 
  названия полей, типы значений, коды справочников и существование документов, на которые
  ссылаются поля. При ошибке ничего не записывается, а модель получает список
  того, что исправить.
- Объекты открывает администратор, выдавая ассистенту **разделы админки** в
  профиле безопасности. Например, раздел «Дизайнер» открывает агенты,
  удалённые действия, выборки, документообороты и уведомления. Объекты
  невыданных разделов HCM не примет.
- Удалять документы ассистент не умеет!!! И не будет даже, если попросить из LLM.
- Каждая попытка записи попадает в журнал `logs/writes-ГГГГ-ММ-ДД.log`. В
  журнале видно, что прислала модель, что ассистент отправил в HCM и что HCM
  ответил. Журнал хранится год и в выгрузку телеметрии не входит.

> **Важно.** Документы с кодом — агенты, удалённые действия, выборки и т.п. — HCM
> выполняет на своём сервере. Если открыть раздел «Дизайнер», модель
> сможет создать агента с произвольным кодом. Выдавайте только нужные
> разделы. Заведите для ассистента отдельное удостоверение. Там, где запись
> не нужна, оставьте `HCM_API_URL` пустым.

## Настройка

### 1. Скачайте профиль Open API

Профиль — XML-файл со списком объектов, которые Open API может создавать и
изменять. Ассистент генерирует его под вашу версию HCM. Скачать его можно двумя
способами:

- в дашборде кнопкой со стрелкой вниз в правом верхнем углу;
- командой:

```bash
curl -H "Authorization: Bearer <MCP_AUTH_TOKEN>" http://localhost:3100/hcm-api/profile.xml -o ws_hcm_ai_assistant.xml
```

Положите файл на сервер HCM:
`<WebSoftServer>/wtv/oapi/profiles/ws_hcm_ai_assistant.xml`.

Профиль в HCM — это копия, сам ассистент его не обновляет: каталог HCM
подключён к контейнеру только на чтение. Файл устаревает, когда меняется
состав объектов HCM: после обновления HCM, включения или отключения
компонента. Ассистент сверяет этот файл со своим списком объектов при
старте и расхождение показывает в дашборде:

- **«Профиль Open API устарел»** — в HCM есть объекты, которых нет в файле,
  или у объектов сменились разделы админки. Такие объекты ассистент
  создавать не сможет, остальные работают.
- **«Профиль Open API не подходит этой версии HCM»** — в файле есть
  объекты, которых в HCM больше нет. HCM не строит описание API, и запись
  не работает ни для одного объекта.

В обоих случаях скачайте профиль заново, замените файл и перезапустите HCM.
Новые объекты ассистент узнаёт при своём перезапуске, поэтому после
обновления HCM сначала перезапустите ассистент (`docker compose restart`),
потом скачивайте профиль.

### 2. Профиль безопасности

В админке откройте **Безопасность → Профиль безопасности** и создайте
новый профиль, например «AI-ассистент»:

1. «Источник» — **Файл на локальном диске**.
2. «Добавить строку» — выберите разделы, объекты которых ассистенту можно
   создавать и изменять: «Дизайнер» (агенты, действия, выборки,
   документообороты, уведомления, показатели, шаблоны, отчёты), «Дистанционное
   обучение» (курсы, тесты), «Учебный центр» (мероприятия) и т.п.
3. В колонке «Профиль» у каждой строки выберите **ws_hcm_ai_assistant**.
   Если его нет в списке, либо файл из шага 1 лежит не в той папке, либо нужно ребутнуть HCM.
4. Сохраните.

### 3. Удостоверение

**Безопасность → Удостоверение**, новое:

- «Тип» — **Basic**;
- «Логин» и «Пароль» — придумайте, они пойдут в `.env` ассистента;
- «Профиль безопасности» — профиль из шага 2.

### 4. Внешнее приложение API

**Безопасность → Внешние приложения API**, новое:

- «APP ID» — любая строка без пробелов, например `ws_hcm_ai_assistant`;
- «Удостоверения» → «Выбрать…» — удостоверение из шага 3.

### 5. Перезапустите HCM

Описание API платформа кеширует на сутки. Новый профиль и разделы HCM увидит
после перезапуска. Это нужно и после любой правки профиля безопасности или
файла профиля.

### 6. Заполните `.env` ассистента

```
HCM_API_URL=http://hcm-server
HCM_API_APP_ID=ws_hcm_ai_assistant
HCM_API_LOGIN=<логин удостоверения>
HCM_API_PASSWORD=<пароль удостоверения>
```

`HCM_API_URL` — адрес сайта HCM, как его видит контейнер ассистента. Внутри
контейнера `localhost` — это сам контейнер, поэтому укажите имя или IP
машины с HCM. Затем выполните:

```bash
docker compose up -d
```

### 7. Проверьте

- `http://localhost:3100/readyz`: в `hcm_api` должно быть
  `"configured": true, "status": "ok"`. Статус `error` означает, что HCM
  не принял учётные данные или недоступен. Подробности — в уведомлении
  дашборда.
- Там же `"profile": "ok"` — файл профиля в HCM совпадает с объектами.
  `stale` — профиль устарел, `broken` — не подходит этой версии HCM (см.
  шаг 1). `not_found` — ассистент не нашёл файл в `wtv/oapi/profiles/`
  каталога HCM: запись работать может, если файл лежит в другом каталоге,
  но сверить его ассистент не может.
- В LLM-клиенте попросите: «покажи шаблон для создания агента сервера».
  В ответе `get_document_template` будет строка «Запись: … объект открыт
  профилем ассистента».
