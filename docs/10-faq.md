# 10. Частые вопросы

## Безопасность

**AI Assistant может что-нибудь изменить в базе?**
Нет. Каждый запрос выполняется в транзакции, которая в конце безусловно
откатывается: в PostgreSQL — `BEGIN TRANSACTION READ ONLY`, в MS SQL —
`BEGIN TRAN` с `ROLLBACK`. Плюс проверка текста запроса перед выполнением.
Даже если бы AI Assistant попытался записать — транзакция не зафиксируется.
Пользователю базы всё равно давайте только чтение.

**А в каталоге WebSoftServer?**
Он смонтирован в режиме `ro`: запись невозможна на уровне Docker.

**Куда уходят данные?**
Никуда. AI Assistant работает внутри вашей сети и наружу не обращается — кроме
однократной загрузки модели поиска, если вы включите
`SEARCH_HYBRID_ENABLED=true`. Телеметрия лежит в вашем каталоге `logs/`, пока
вы сами не пришлёте архив.

**Что видит LLM-провайдер?**
То, что модель получила в ответ на вызов инструмента: схемы, код платформы и
строки данных, если модель их запросила. Это обычный контекст диалога — как
если бы разработчик сам вставил фрагмент в чат. Решайте, какие базы
подключать, исходя из этого. Подключите БД с DEV контура.

**Кто может обратиться к серверу?**
Любой, кто видит порт и знает `MCP_AUTH_TOKEN`.

## Производительность

**Почему первый старт такой долгий?**
AI Assistant разбирает схему платформы: около тысячи файлов `*.xmd` и настройки из
базы. Одна–пять минут на локальном диске, дольше через сетевую шару.
Дальше данные лежат в памяти и обновляются по таймеру.

**Что такое `search_mode` в `/readyz`?**
Режим поиска по функциям платформы: `bm25` — по словам (работает сразу),
`hybrid_building` — досчитываются векторы в фоне, `hybrid` — поиск понимает
формулировки «своими словами». Гибрид включается настройкой
`SEARCH_HYBRID_ENABLED=true`; первый расчёт занимает несколько минут, дальше
векторы берутся из кеша в `./models`.

**Сервер держит подключение к базе постоянно?**
Да, пул подключений. Данные настроек перечитываются по таймеру (около 1 раза в
5 минут), данные записей объектов — только по запросу модели.

## Эксплуатация

**Сколько разработчиков может работать с одним сервером?**
Сколько угодно: они подключаются по HTTP, каждый в своей сессии. Один AI Assistant
на инстанс HCM — оптимальная схема.

**Можно подключить несколько баз HCM?**
Один контейнер — одна база. Для второй базы поднимите второй контейнер с
другим каталогом, своим `.env` и другими портами.

**Можно запустить без Docker?**
Пока нет: поставляется только образ.

**Есть режим stdio (как у Claude Desktop)?**
Пока нет. Клиенты подключаются по HTTP; это же позволяет
одному серверу обслуживать всю команду.

**Что будет, если сетевая шара с каталогом платформы отвалится после старта?**
Сервер продолжит работать: схема уже в памяти. Инструменты, которые читают
файлы кода (`include_code=true`), вернут пометку, что файл недоступен.
Обновление схемы произойдёт при следующем перезапуске.

**Мы обновили платформу. Что делать?**
Перезапустить контейнер: `docker compose up -d`. Схема и код читаются при
старте. Если каталог у вас копия — сначала обновите копию.

**Почему версия выглядит как `2.3.0-beta.1525`?**
`2.3.0` — версия сервера, суффикс `1525` — сборка Websoft HCM, по которой
сверен встроенный справочник платформы. Это **не** версия вашей HCM: её
сервер определяет сам и показывает в `/readyz` в поле `hcm_version`. Сервер
работает и с другими сборками; если метод платформы у вас отличается от
описания в справочнике, инструмент показывает фактическую сигнатуру из вашего
инстанса.

**Почему модель иногда всё равно выдумывает имена полей?**
Потому что её никто не обязал спросить. Подключите правила из
[05-prompts.md](05-prompts.md) — они как раз об этом. Если и с ними модель
идёт мимо инструментов, это интересный материал для Issue: пришлите выгрузку
телеметрии, по ней видно, что она вызывала :-).

**Модель зовёт инструмент, а он отвечает пустотой. Это ошибка?**
Не обязательно: возможно, в вашем инстансе такого объекта нет. Но если вы
знаете, что объект есть, — это интересный материал для Issue: пришлите выгрузку
телеметрии, по ней видно, что она вызывала :-).
