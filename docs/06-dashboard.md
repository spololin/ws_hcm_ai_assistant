# 6. Дашборд

Дашборд показывает, как модели используют AI Assistant:
какие инструменты помогают, где модель повторяет запрос и где получает пустой
ответ. Он же собирает архив для обратной связи.

Адрес: **http://&lt;хост&gt;:3100/dashboard/**

Работает, если в `.env` включены `DASHBOARD_ENABLED=true` и
`MCP_TELEMETRY_ENABLED=true`.

## Вход

При первом открытии страница просит токен — тот же `MCP_AUTH_TOKEN`, что и у
клиентов. Он сохраняется в браузере. Если `MCP_AUTH_TOKEN` пуст, дашборд
открыт всем, кто видит порт.

## Страницы

| Страница | Что показывает |
| --- | --- |
| **Обзор** | Карточка лицензии, карточка окружения (версии MCP и HCM, СУБД, история запусков), доля задач, доведённых до конца, число вызовов, самые проблемные инструменты |
| **Инструменты** | По каждому инструменту: вызовы, доля пустых ответов, повторов, «отступлений» на другой инструмент, среднее время; клик — подробности и примеры запросов |
| **Сессии** | Подключения клиентов: приложение и версия, модель (если она себя назвала), цепочка вызовов внутри сессии |
| **Отзывы** | Что модель написала в `record_feedback`: какие инструменты помогли, чего не хватило |
| **Динамика** | Графики по времени: вызовы, ошибки, пустые ответы |
| **Мониторинг** | Доступность сервера HCM, порталов и СУБД: состояние сейчас, доступность за период, простои с первой ошибкой, время ответа. Работает при `MONITOR_ENABLED=true` |
| **СУБД** | Что не собирается и почему (с командой для администратора базы), аномалии, блокировки — кто держит и кто ждёт, графики сессий и нагрузки, статистика времени выполнения запросов за период и накопленная в СУБД, ожидания, таблицы и индексы. Работает при `DB_MONITOR_ENABLED=true` |
| **Выгрузка телеметрии** | Сбор архива для разработчика — см. [07-feedback.md](07-feedback.md) |

## Уведомления

Если с сервером что-то не так, над каждой страницей появляется уведомление о причине. 
Сейчас сообщается о трёх случаях:
- гибридный поиск включён, но не работает (см.[09-troubleshooting.md](09-troubleshooting.md#гибридный-поиск-не-работает));
- запись в HCM настроена, но Open API HCM её не принимает (см.[ 11-write-api.md](11-write-api.md#если-запись-не-работает));
- профиль Open API в HCM устарел или не подходит версии HCM (см. [11-write-api.md](11-write-api.md#1-скачайте-профиль-open-api));
- монитор: сервер HCM, СУБД или портал не отвечают две проверки подряд; монитор СУБД собирает не всё из-за прав или настроек (с командой); письмо о недоступности не настроено или не ушло.

## Мониторинг и СУБД

Обе вкладки по умолчанию выключены. **Мониторинг** включается `MONITOR_ENABLED=true`:
ассистент раз в минуту открывает адрес сервера из `HCM_API_URL`, проверяет базу и
порталы из таблицы `hosts` базы HCM (портал за обратным прокси — по внешнему
адресу). Портал, который с сервера ассистента не открывается или больше не нужен,
уберите из проверки: `MONITOR_EXCLUDE_HOSTS=test.company.local,10.0.0.5:8080`.

**Письма о недоступности** — `MONITOR_MAIL_ENABLED=true` вместе с мониторингом.
Когда сервер HCM, база или портал не отвечают две проверки подряд, ассистент шлёт
письмо; когда снова доступны — второе, с длительностью простоя. Все изменения одной
проверки — одним письмом: если лежит сервер, порталы на нём не придут десятком писем.
Получатели — адреса из `MONITOR_MAIL_TO` и сотрудники группы HCM из
`MONITOR_MAIL_GROUP` (код или id группы): писем получат участники с почтой, кроме
уволенных; состав группы ассистент перечитывает сам. SMTP-сервер — свой у
ассистента (`MONITOR_MAIL_SMTP_*`, `MONITOR_MAIL_FROM`), а не HCM: письмо должно уйти,
когда HCM или база недоступны. Кнопка «Отправить тестовое письмо» на вкладке
проверяет настройки сразу и показывает, кому ушло письмо и кого отбросили (нет
почты, адрес не похож на почту, уволен). Если письмо не ушло, над страницами
появится уведомление, а ассистент повторит отправку на следующей проверке.

Пример настройки в `.env` (почтовый сервер с STARTTLS на порту 587):

```
MONITOR_ENABLED=true
MONITOR_MAIL_ENABLED=true
MONITOR_MAIL_SMTP_HOST=smtp.company.local
MONITOR_MAIL_SMTP_PORT=587
MONITOR_MAIL_SMTP_USER=hcm-monitor@company.local
MONITOR_MAIL_SMTP_PASSWORD=пароль
MONITOR_MAIL_FROM=Ассистент HCM <hcm-monitor@company.local>
MONITOR_MAIL_TO=admin@company.local
MONITOR_MAIL_GROUP=hcm_admins
```

SMTP на порту 465 — добавьте `MONITOR_MAIL_SMTP_SECURE=true`; сервер без
авторизации — оставьте `MONITOR_MAIL_SMTP_USER` и `MONITOR_MAIL_SMTP_PASSWORD` пустыми.

**СУБД** включается `DB_MONITOR_ENABLED=true`. Для сессий, ожиданий и статистики
времени выполнения пользователю базы нужны дополнительные права — какие именно, вкладка
покажет сама, а команды есть в [02-database-user.md](02-database-user.md#для-монитора-субд-необязательно).
Пока прав нет, раздел помечен «нет прав», а не показывает пустоту как «всё хорошо».

История хранится на сервере ассистента (`logs/monitor.sqlite`) и в выгрузку
телеметрии не входит. Те же данные модель получает инструментами
`get_server_status` и `get_db_health`: на вопросы «падал ли портал вчера в обед»
или «что грузило базу ночью» она отвечает по истории, а не догадками.

## Профиль Open API

Кнопка со стрелкой вниз в правом верхнем углу скачивает
`ws_hcm_ai_assistant.xml` с url `/hcm-api/profile.xml`. Это профиль для записи в HCM, 
его нужно положить в `<WebSoftServer>/wtv/oapi/profiles/`. Подробнее — [11-write-api.md](11-write-api.md).

## На что смотреть

- **Пустые ответы** у поисковых инструментов — модель спрашивает не теми
  словами либо в вашей инсталляции такого объекта нет. Интересный случай:
  напишите в Issue, какой был запрос.
- **Повторы** — модель переспрашивает то же самое: обычно значит, что ответ
  оказался непонятным.
- **Отступления** — модель не получила ответа от одного инструмента и пошла
  к другому (чаще всего к `execute_sql`). Это сигнал, что нужного инструмента
  не хватило.

Ровные цифры без проблем тоже полезны: значит, инструмент работает как надо.

## Если дашборд не открывается

- `DASHBOARD_ENABLED=false` в `.env` — включите и выполните
  `docker compose up -d`;
- адрес без завершающего слеша (`/dashboard`) — добавьте слеш;
- `401` — неверный токен, нажмите «выйти» на странице входа и введите заново.

Остальное — [09-troubleshooting.md](09-troubleshooting.md).
