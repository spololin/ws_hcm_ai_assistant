# 1. Что нужно для установки

## Docker

| Система | Что ставить |
| --- | --- |
| Windows 10/11 | Docker Desktop (с включённым WSL2) |
| macOS | Docker Desktop |
| Linux | Docker Engine + плагин `docker compose` |

После установки выполнить в консоли `docker version` и `docker compose version`.

Требуемый результат: обе команды печатают версии клиента и сервера. Если
`docker compose version` не работает, а `docker-compose --version` работает —
у вас старая версия Compose (v1); поставьте плагин v2, команды в инструкции
рассчитаны только на него.

На Windows Docker Desktop должен быть в режиме **Linux containers** (по
умолчанию так и включен, но лучше проверить).

## Доступ к базе данных HCM

- СУБД: **PostgreSQL** или **MS SQL Server** — та, на которой работает ваша HCM. 
  На MS SQL функционал не тестировался, так что как повезет! Может что и будет работать...
- Достаточно прав **только на чтение**; как создать такого пользователя —
  [02-database-user.md](02-database-user.md).
- Машина с Docker должна видеть сервер базы по сети (для MS SQL — открытый
  TCP-порт, обычно 1433; для PostgreSQL — 5432).

Сервер читает из базы объекты платформы: объекты, справочники, системные
события, документообороты... в общем всё. Данные сотрудников он
читает только тогда, когда об этом просит модель через инструменты.

## Каталог WebSoftServer

Сервер разбирает схему платформы из файлов инстанса: `wtv/wtv_common.xml`,
`*.xmd`, а по запросу модели — исходный код обработчиков событий, действий, выборок,
агентов и т.п. Часто изменяемые объекты, например, настраиваемые поля,
хранятся в кеше с TTL от 45 до 300 секунд и обновляются после истечения кеша.

Нужен доступ на **чтение** к корню каталога `WebSoftServer` с той машины, где
запускается Docker. Варианты (папка на хосте, сетевая шара, копия) разобраны в
[03-install.md](03-install.md), раздел «Где лежит каталог WebSoftServer».

## Ресурсы

| Что | Сколько |
| --- | --- |
| Образ | ~1,2 ГБ на диске |
| Память контейнера | 500–800 МБ при работе |
| Диск под логи | 30-40 мегабайт в неделю, но зависит от активности использования |
| Модель поиска | ещё ~120 МБ, только если `SEARCH_HYBRID_ENABLED=true` |

Первый старт занимает 2-5 минут: сервер читает схему платформы. Через сетевую шару — дольше.

## Сеть

По умолчанию сервер слушает порты **3100** (основной) и **3101** (совместимость
со старыми клиентами) на машине с Docker и доступен из локальной сети. Доступ
ограничивает токен `MCP_AUTH_TOKEN`, а не сетевая видимость — обязательно задайте токен!

Если разработчики работают на той же машине, порты можно закрыть от сети:
в [docker-compose.yml](../docker-compose.yml) у строк `ports` верните префикс
`127.0.0.1:`.

## Интернет

Не нужен, кроме двух моментов: скачивания образа и — если вы включите
гибридный поиск — однократной загрузки модели поиска. Всё остальное работает
внутри вашей локальной сети. Подробнее в 
[09-troubleshooting.md](09-troubleshooting.md).
