# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [семантические](https://semver.org/lang/ru/).

Номер версии выглядит как `2.3.0-beta.1525`. Суффикс `.1525` — сборка Websoft HCM,
по которой сверен справочник платформы внутри сервера, а не версия инстанса HCM
(её сервер определяет сам и показывает в `/readyz` в поле `hcm_version`).
`2.3.0-beta` - версия AI ассистента.

## [Unreleased]

## [2.4.0-beta.1525] — 2026-09-24

### Добавлено

- **Каталоги без собственного документа** — функциональные руководители
  (`func_managers`), участники групп и мероприятий, объекты с метками и другие
  каталоги, строки которых платформа строит из документов других объектов, —
  теперь находятся как объекты. Список составляется при каждом запуске ассистента.
- **Настраиваемые поля вложенных элементов**, например поля задач типовой
  программы развития: `get_object_schema` показывает их отдельным разделом с
  готовым запросом «строка на задачу», `find_field` находит по имени и
  названию, `get_object_relations` показывает ссылки таких полей на другие
  объекты. Раньше эти поля не были видны ни одному инструменту.
- У настраиваемых полей в `get_object_schema` виден объект, на который
  ссылается поле, и допустимые значения поля-списка.

### Изменено

- **Пользовательские типы документов (`cc_*`) видны без перезапуска.**
  Новый тип, новое поле существующего типа и удалённый тип подхватываются в
  течение минуты; раньше требовался перезапуск контейнера. 
  `refresh=true` в инструментах объектов по-прежнему перечитывает сразу.
- **Данные инструментов с карточками обновляются через минуту, а не через пять.**
  Раз в минуту сервер запросом сверяет число записей и даты изменения в
  базе и перечитывает данные только при изменении — нагрузка на базу меньше,
  чем раньше. Правка файла библиотеки кода тоже видна через минуту. Правку,
  которую платформа не отметила датой (например, сохранение документа
  скриптом), сервер подхватывает не позже чем через 30 минут.
- Настраиваемые поля перечитываются из базы только тогда, когда шаблон полей
  действительно изменился: сервер сверяет дату и хеш шаблона запросом.
- Если обновить данные библиотек кода из базы не удалось, `get_code_libraries`
  отвечает прежними данными, а не ошибкой.
- Почти все инструменты поиска получили параметр `refresh` для принудительного считывания из БД.

### Как обновиться

`docker compose pull` и `docker compose up -d`, затем перезапустите
MCP-клиент в IDE — иначе модель не увидит новый параметр `refresh` у
инструментов. `git pull` — по желанию: обновилась только документация.

### Новые переменные .env

Со значением по умолчанию — старый `.env` продолжает работать.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `UDT_SCHEMAS_TTL_SEC` | `60` | Как часто проверять, не изменились ли пользовательские типы документов |
| `CACHE_FULL_RELOAD_SEC` | `1800` | Не реже чем раз в столько секунд данные кешей перечитываются целиком, даже если проверка изменений ничего не заметила |

## [2.3.2-beta.1525] — 2026-09-24

### Исправлено

- **Подсказка про сертификат.** Раньше она и документация предлагали
  раскомментировать строку `NODE_EXTRA_CA_CERTS` в `.env`, а у тех, кто
  обновлялся с прошлой версии, такой строки нет: `git pull` меняет только
  `.env.example`. Теперь подсказка на дашборде, в `/readyz` и в логе даёт
  строку целиком — `NODE_EXTRA_CA_CERTS=/app/certs/ca.pem` — и команду
  `docker compose up -d`.
- **Документация:** `.env` применяет только `docker compose up -d`, а
  `docker compose restart` и перезапуск в Docker Desktop оставляют прежние
  настройки — об этом теперь сказано в
  [docs/08-update.md](docs/08-update.md) и
  [docs/09-troubleshooting.md](docs/09-troubleshooting.md).

### Как обновиться

`docker compose pull` и `docker compose up -d`. `git pull` — по желанию:
изменилась только документация.

## [2.3.1-beta.1525] — 2026-09-24

### Исправлено

- **Сервер больше не перезапускается по кругу, если модель гибридного поиска
  не скачалась.** Раньше при `SEARCH_HYBRID_ENABLED=true` без доступа к
  huggingface.co контейнер падал при каждом старте. Теперь сервер работает с
  поиском по словам, а причина и что с ней делать видны на дашборде, в
  `/readyz` (поля `search_error` и `search_hint`) и в `logs/errors-<дата>.log`.
- **В логе видна настоящая причина сетевой ошибки.** Вместо одного
  `fetch failed` пишется код: `SELF_SIGNED_CERT_IN_CHAIN`, `ENOTFOUND` и т. п.

### Добавлено

- **Свой корневой сертификат**, если HTTPS перехватывает антивирус
  (Kaspersky, ESET и другие с проверкой защищённых соединений) или прокси:
  файл кладётся в папку `certs` рядом с `docker-compose.yml`, в `.env`
  раскомментируется строка `NODE_EXTRA_CA_CERTS`. Как выгрузить сертификат на
  Windows, macOS и Linux — [docs/09-troubleshooting.md](docs/09-troubleshooting.md).
  Там же — как скачать модель поиска вручную, без сертификата и без доступа
  контейнера в интернет.
- **Уведомление на дашборде**, если гибридный поиск включён, но не работает:
  над каждой страницей, с причиной и подсказкой.
- **Строка `server ready` в конце старта** — с адресами MCP, SSE и дашборда.
  После неё консоль молчит, и раньше сервер выглядел зависшим.

### Как обновиться

В этот раз обновите и файлы этого репозитория: в новом `docker-compose.yml` подключена
папка `certs`. В папке ассистента выполните `git pull`, затем
`docker compose pull` и `docker compose up -d`. Свои правки в
`docker-compose.override.yml` сохранятся. Подробнее в [docs/08-update.md](docs/08-update.md).

### Новые переменные .env

Со значением по умолчанию — старый `.env` продолжает работать.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `NODE_EXTRA_CA_CERTS` | не задана | Файл с корневым сертификатом, если HTTPS перехватывает антивирус или прокси (`/app/certs/ca.pem`) |

## [2.3.0-beta.1525] — 2026-09-24

Первый публичный выпуск бета-версии: сервер поставляется Docker-образом,
исходники в него не входят.

### Изменено

- **Токен доступа стал обязательным.** Если `MCP_AUTH_TOKEN` в `.env` пуст,
  контейнер останавливается сразу и пишет в лог, как сгенерировать токен.
  См. [docs/03-install.md](docs/03-install.md).
- Обновлена среда выполнения внутри образа: у прежней версии поддержка
  закончилась 30 апреля 2026 года, и обновления безопасности для неё больше
  не выходят. Ни настроек, ни работы сервера это не меняет.
- Оптимизирован логгер. Из вывода контейнера убраны служебные строки 
  веб-сервера при старте (список модулей и маршрутов),
  повторы HTTP-запросов и вызовов инструментов — у каждого есть свой файл
  в `logs/`.
- Справочные разделы инструментов сверены с Websoft HCM 2025.2.1525.

### Исправлено

- **MS SQL: запросы к базам, где колонка с данными объекта описана схемой.**
  На таких базах часть запросов отклонялась сервером базы целиком — 
  инструмент отвечал ошибкой, а не пустым результатом.
- **Списки «где используется» больше не пропадают целиком.** Такой список
  собирается из нескольких настроек платформы, и если одной из них в вашей
  версии HCM нет, раньше терялся весь список: например, у документооборотов
  не показывалось ни одного места использования. Теперь недоступный источник
  пропускается, остальные остаются, а в `startup-*.log` появляется
  предупреждение.
- **Настраиваемые поля с датами.** Если в поле-дате лежали значения в разном
  формате (`2007-06-26T00:00:00+00:00` и `29.06.2009 00:00:00`),
  запрос падал. Теперь такие значения читаются корректно в обеих СУБД.

### Как обновиться

Установка: [docs/03-install.md](docs/03-install.md).
Обновление: [docs/08-update.md](docs/08-update.md).
