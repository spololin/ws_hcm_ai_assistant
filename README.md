# WebSoft HCM AI Assistant (beta)

AI-ассистент подойдет в первую очередь разработчикам, администрторам, аналитикам, тестировщикам, 
разрабатывающим на платформе **Websoft HCM**. Ассисент может получать данные по любым объектам системы. 
Подключается к LLM-клиенту (Cursor, VS Code, Kilo Code, Claude Code, OpenCode и т.п.)
по протоколу MCP и даёт модели точные сведения о инстансе HCM: объекты и их 
поля, схемы объектов, связи полей, функции системы, tools и библиотек, контекст объектов, 
код и настройки объектов, а также выполняет чтение данных из БД. 

Ассистент подойдет любым классам моделей. 

С ассисетнтом эффективность слабых и средних моделей возрастает в разы. 

Модель перестаёт выдумывать имена объектов, полей и функций SP-XML.

> ВАЖНО!!! Это beta-версия: ассистент рабочий, но пока еще пробуется на различных задачах.
> 
> ВАЖНО!!! Пока нет разграничения запросов по ролям и доступам. Каждый получает любые данные!

## Что нужно для запуска

- Docker (Docker Desktop на Windows или macOS, Docker Engine на Linux);
- доступ к базе данных HCM (MS SQL или PostgreSQL) — достаточно прав на чтение;
- каталог `WebSoftServer` инстанса, доступный машине с Docker — достаточно прав на чтение.

Подробно про подготовку — [docs/01-requirements.md](docs/01-requirements.md).

## Быстрый старт

1. Создайте пользователя базы с правом только на чтение —
   [sql/](sql/), инструкция в [docs/02-database-user.md](docs/02-database-user.md), или (кто не боится) 
   взять кредлы из `spxml_unibridge_config.xml`.
2. Склонируйте этот репозиторий `git clone https://github.com/spololin/ws_hcm_ai_assistant.git`.
3. Переименуйте `.env.example` в `.env`.
4. Заполните в `.env`: `HCM_HOST_PATH`, `DB_*`, `MCP_AUTH_TOKEN` (токен
   обязателен — с пустым значением сервер не запустится).
   Остальные поля не меняются.
5. Выполните `docker compose up -d`
6. Подождите первый старт (до 10 минут в зависимости от ресурсов - сервер читает 
   схему объектов инстанса).
7. Проверьте `curl http://localhost:3100/readyz` - должно быть `"status":"ready"`.
8. Подключите LLM-клиент — [docs/04-clients.md](docs/04-clients.md).
9. Задаем вопросы про объекты, пишем промпты и код в LLM клиенте.
10. При желании/возможности раз в неделю присылайте выгрузку телеметрии —
   [docs/07-feedback.md](docs/07-feedback.md).

Подробно про установку — [docs/03-install.md](docs/03-install.md).

## Качество поиска

Поиск по функциям платформы (`find_sp_xml_entities`: методы tools, функции
библиотек программного кода, встроенные функции SP-XML) проверяется набором
из 60 запросов. Они сформулированы так, как пишет пользователь: «назначить
курс», «проверить пользователя на руководителя», «выгрузить отчёт в xlsx».
Для каждого запроса заранее записан правильный ответ, а замер смотрит, на
каком месте поиск его выдал.

Замер от 22 сентября 2026 года, версия AI Assistant 2.3.0-beta.1525:

| Версия HCM | Режим поиска | Первым Hit@1 | В первой пятёрке Hit@5 | В первой десятке Hit@10 | MRR |
| --- | --- | --- | --- | --- | --- |
| 2025.2.1525 | гибридный | 69% (27 из 39) | 79% (31) | 90% (35) | 0.74 |
| 2025.2.1525 | по словам | 49% (19 из 39) | 62% (24) | 67% (26) | 0.55 |
| 2023.1.3.589 | гибридный | 64% (25 из 39) | 77% (30) | 82% (32) | 0.69 |
| 2023.1.3.589 | по словам | 46% (18 из 39) | 62% (24) | 64% (25) | 0.52 |

Как читать таблицу:

- **Первым, в пятёрке, в десятке** (Hit@1, Hit@5, Hit@10) — доля запросов,
  где правильный ответ стоит на первом месте, среди первых пяти или первых
  десяти результатов. Если правильных ответов несколько, засчитывается любой.
- **MRR** (средняя обратная позиция) — среднее от «1 / место правильного
  ответа»: 1 — всегда первым, 0.5 — в среднем вторым, 0 — не найден.
- **Режим поиска** задаёт `SEARCH_HYBRID_ENABLED` в `.env`. Поиск по словам
  работает сразу. Гибридный понимает формулировки своими словами, но при
  первом старте несколько минут считает векторы — см.
  [docs/10-faq.md](docs/10-faq.md).
